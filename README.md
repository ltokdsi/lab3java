## Задание 1.

### Задача 1.3: Квадрат и Сторона Квадрата
#### Текст задачи
Создайте сущность Квадрат. Квадрат описывается следующими характеристиками:
- Имеет Точку (из задачи 1.4.1), отмечающую левый верхний угол.
- Имеет длину стороны.
- Создается путем указания точки левого верхнего угла и размера стороны.
- Создается путем указания координаты X и Y левого верхнего угла и размера стороны.
- Может быть приведен к строке вида `"Квадрат в точке T со стороной N"`, где N — длина стороны, а T — результат приведения к строке верхнего левого угла.
- Может возвращать новую Ломаную (из задачи 1.5.7), точки которой соответствуют точкам углов текущего квадрата.

Необходимо выполнить следующие задачи:
1. Создайте Квадрат в точке {5;3} со стороной 23.
2. Присвойте в ссылку типа Ломаная результат вызова метода получения Ломаной у ранее созданного квадрата.
3. Выведите на экран общую длину полученной Ломаной.
4. Сдвиньте последнюю Точку Ломаной в позицию {15;25}.
5. Снова выведите на экран длину Ломаной.

Измените сущность Квадрат. Гарантируйте, что Квадрату невозможно задать отрицательное значение длины стороны. При попытке задать сторону равной нулю или менее, выбрасывается ошибка с соответствующим текстом. Контроль должен осуществляться как во время создания объекта, так и позднее, в случае если будет необходимо менять размеры Квадрата. Необходимо предоставить возможность изменения длины стороны Квадрата и возможность узнать размер стороны.
#### Алгоритм решения
Создается класс `Square` с приватными полями `topLeft` (типа `Point`) и `side` (типа `double`). Реализуются два перегруженных конструктора: один принимает объект `Point` и сторону, второй — координаты `x`, `y` и сторону. В сеттере `setSide()` выполняется проверка: если переданное значение `<= 0`, выбрасывается исключение `IllegalArgumentException`. Конструктор вызывает этот же сеттер, что гарантирует защиту и при создании объекта. Метод `getPolygonalChain()` вычисляет координаты всех четырех углов квадрата и возвращает новый объект `Polyline`.

## Задание 2.

### Задача 2.4: Бинарное дерево
#### Текст задачи
Необходимо реализовать структуру данных, представляющую собой простейшее бинарное дерево. Для формирования данного дерева будет использоваться сущность Узел.
Состояние сущности описывается следующими характеристиками:
- Значение, целое число.
- Родитель, Узел.
- Левый потомок, Узел.
- Правый потомок, Узел.

Инициализация сущности выполняется без аргументов.
Поведение сущности описывают следующие действия:
- Добавление значения (если значение не задано — задается; если задано — большее идет в правого потомка, меньшее или равное — в левого).
- Удаление значения (удаляется узел с этим значением, но все его потомки должны остаться прикрепленными к структуре).
- Проверка на существование значения.
- Приведение к строке (перечень всех значений, полученный левосторонним обходом в глубину).

После реализации сущности, создайте её экземпляр и добавьте в него числа: 3, 5, 4, 7, 1, 2. Выведите на экран текстовое представление узла.
#### Алгоритм решения
Создается класс `Node` с полями `value` (типа `Integer`, чтобы изначально значение могло быть `null`) и ссылками на `parent`, `left`, `right`. В методе `add(int val)` рекурсивно ищется место для вставки: значения больше текущего уходят в правое поддерево, меньше или равные — в левое. В методе `contains(int val)` выполняется рекурсивный поиск. Метод `remove(int val)` обрабатывает три случая удаления: лист (просто отвязывается от родителя), узел с одним потомком (данные потомка переносятся в текущий узел) и узел с двумя потомками (значение заменяется минимальным элементом из правого поддерева). В `toString()` реализован рекурсивный левосторонний обход (левое поддерево -> текущее значение -> правое поддерево).

## Задание 3.

### Задача 3.2: Замкнутая ломаная
#### Текст задачи
Создайте такой подвид сущности Ломаная, полученной в задаче 1.5.7, которая будет представлять собой замкнутую ломаную линию, то есть последовательность точек, начинающихся и заканчивающихся на одной и той же точке. Данная сущность во всех отношениях совпадает с обычной Ломаной, кроме расчета длины.
#### Алгоритм решения
Создается класс `ClosedPolyline`, наследующийся от `Polyline` с помощью ключевого слова `extends`. Конструкторы вызывают конструкторы родителя через `super()`. Переопределяется метод `getLength()`: сначала берется обычная длина через `super.getLength()`, после чего (если точек больше двух) к результату прибавляется расстояние между последней и первой точками списка.

## Задание 4.

### Задача 4.4: Фигуры
#### Текст задачи
Необходимо продумать структуру и организацию следующих геометрических фигур:
1. Круг. Задается точкой координат центра и радиусом.
2. Квадрат. Рекомендуется взять квадрат, полученный в задаче 2.1.3.
3. Прямоугольник. Задается точкой координат левого верхнего угла и двумя сторонами.
4. Треугольник. Задается тремя точками координат.

Для каждой фигуры обязательно должна быть возможность рассчитать её площадь.
#### Алгоритм решения
Создается абстрактный класс `Figure` с единственным абстрактным методом `getArea()`. От него наследуются классы `Circle`, `Square`, `Rectangle` и `Triangle`. В каждом наследнике переопределяется метод `getArea()` по соответствующей геометрической формуле (для круга `π * r²`, для квадрата `side²`, для прямоугольника `width * height`, для треугольника — формула площади по координатам трех вершин). Это позволяет хранить разные фигуры в одном массиве типа `Figure[]` и вычислять их площади полиморфно.

## Задание 5.

### Задача 5.5: Измерение длины
#### Текст задачи
Разработайте метод, который принимает набор объектов, у которых можно посчитать длину, и возвращает сумму длин принятых объектов. Измените сущности, полученные в задачах 1.5.7 (Ломаная линия) и 1.6.6 (Линия), таким образом, чтобы их можно было передать в этот метод. Продемонстрируйте работоспособность метода на примерах.
#### Алгоритм решения
Создается интерфейс `Measurement` с методом `double getLength()`. Классы `Line` и `Polyline` реализуют этот интерфейс (`implements Measurement`). В классе `Utils` добавляется статический метод `totalLength(Measurement... objects)`, который проходит циклом по всем переданным объектам, вызывает у каждого `getLength()` и возвращает общую сумму.

### Задача 5.7: Ломай меня полностью
#### Текст задачи
Разработайте метод, который принимает такой набор объектов, у которых можно получить ломаную линию, и возвращает их объединение в виде одного объекта типа Ломаная. Передаваемые в метод объекты должны обладать методом со следующей сигнатурой: `public Polyline getPolygonalChain();`. Измените ранее созданные сущности Квадрат, Треугольник, Линия и ЛоманаяЛиния так, чтобы у них также можно было получить ломаную линию и их можно было бы передать в разрабатываемый метод. Обратите внимание, что у круга невозможно получить ЛомануюЛинию.
#### Алгоритм решения
Создается интерфейс `ToPolyline` с методом `Polyline getPolygonalChain()`. Классы `Square`, `Triangle`, `Line` и `Polyline` реализуют этот интерфейс (класс `Circle` его не реализует). В классе `Utils` добавляется метод `mergeChains(ToPolyline... objects)`, который создает новую пустую ломаную, получает ломаную от каждого переданного объекта и копирует все их точки в общий результирующий объект `Polyline`.

## Задание 6.

### Задача 6.4: Сравнение ломаных линий
#### Текст задачи
Измените сущность Ломаная из задачи 1.5.7. Переопределите метод сравнения объектов по состоянию таким образом, чтобы две ломаные считались одинаковыми тогда, когда все их точки совпадают.
#### Алгоритм решения
В классе `Point` переопределяется метод `equals(Object o)` для сравнения двух точек по их координатам `x` и `y`. Затем в классе `Polyline` переопределяется метод `equals(Object o)`, который сравнивает списки точек двух ломаных с помощью `Objects.equals(points, polyline.points)`. Благодаря переопределению в `Point`, сравнение списков корректно проверяет совпадение всех точек по их значениям, а не по ссылкам в памяти.

## Задание 8.

### Задача 8.4: Клонирование точки
#### Текст задачи
Измените сущность Точка. Переопределите метод клонирования, унаследованный от класса `Object`, таким образом, чтобы при его вызове возвращался новый объект Точки, значения полей которого будут копиями оригинальной Точки.
#### Алгоритм решения
В классе `Point` переопределен метод `public Point clone()`, который возвращает новый экземпляр `new Point(this.x, this.y)`. В `Main` демонстрируется, что оригинал и клон — это разные объекты в памяти (`p1 == p2` возвращает `false`), их координаты равны (`p1.equals(p2)` возвращает `true`), а изменение координат клона не влияет на оригинальную точку.
